# Looking at the screens — 2026-08-21

Five screens (login, projects, reviews, review, settings) at 390, 768 and 1440, captured by
`scripts/e2e_browser.mjs` into `output/screens/<width>/<screen>.png` and read one by one.

The images are not committed. They are regenerated by every e2e run and a stored copy would only
tell the next run that the page changed, never whether the change was an improvement. Regenerate
with the e2e command in `CLAUDE.md`.

## What was wrong

**The rules list was cut through the middle of a row.** `max-h-72` on a 1382px list showed five of
thirty-three rules and sliced the fifth through its text, at every width. It read as a rendering
fault rather than as "scroll for more", and on a phone it also put a scroll region inside the page
scroll. The cap is gone; the list flows with the form.

**The Members and Plugin keys forms never formed a row.** Both are written as
`flex flex-wrap items-start gap-2`, but `inputClass` carries `w-full`, and in Tailwind a `width`
utility beats `w-28`/`w-48` — the select computed to 666px inside a 666px container. So every
control sat on its own full-width line, next to a Review setup card laid out as a tidy three-column
grid. They did not look like the same product. `basis-28`/`basis-48` size them instead: a flex-basis
wins over `width` where a competing `width` does not.

**A separator dot dangled at the end of a wrapped line.** On the reviews list at 390 the metadata
row read `#116 · dev@acme.com · main ·` and then wrapped, leaving the last dot with nothing after
it. The dots were their own flex items, so a wrap could strand one. There is now a `Meta` component
that draws the dot before each item, so the separator wraps together with what follows it.

**The review trail printed the payload's JSON keys.** `deterministic_findings: 1 ·
fixed_confirmed: 0 · platform_version: not detected`, and at 1440 the wrap split
`platform_version:` from `not detected`. Underscores are taken out on the way to the screen, and
each key/value is its own box so a wrap cannot break one apart. No label map — that would need
updating every time the server records something new.

**A real file path ran off the side of the page.** Not visible in the first pass, because the e2e
seeded `config/local.properties`. A browser wraps a path after a slash or a hyphen, so only a long
CamelCase segment is a real test: with
`hybris/bin/custom/acme/acmecore/src/com/acme/core/service/impl/DefaultAcmeStorefrontIntegrationService.java`
the document measured 833px wide inside a 390px viewport, and 768 failed too. The seed now writes
that file, and the path paragraph is `break-all`.

**Smaller things.** `1 finding(s) recorded but not counted` is now a real plural. `in progress` was
`text-muted` while `BLOCKED` and `CLEAR` are `font-semibold`; three states of one badge should not
read as three different controls.

## The mechanical check

`captureWidths` in the e2e asserts, at each of the three widths, that the document cannot be
scrolled sideways. The check is only worth having if it can fail, so it was run with `break-all`
removed first:

```
FAIL review at 390px — scrollWidth 833 > viewport 390 —
  p.mt-2.font-mono.text-xs → 818px "hybris/bin/custom/acme/acmecore/src/com/"
```

The culprit is named because the check measures text ranges as well as element boxes. Chrome
reports no oversized box for an overflowing unbreakable string — the element stays inside the card
while its glyphs do not — so an element-only scan finds the page 833px wide and nothing to blame.

## Looked at, left alone

- A long member email (`sebastian.cabarcas@customer-company-name.example`) at 390: the flex row
  shrinks and the text wraps. No overflow.
- The quoted-line `<pre>` with a 130-character Java statement: `overflow-x-auto` contains it, which
  is the right behaviour for code.
- Login at all three widths: centred, nothing to fix.
- The projects list at 390 is mostly leftover `E2E …` projects — twenty-four of them. Not a layout
  problem, but every e2e run creates a project and none removes it, so the screen a developer sees
  in this environment is unrepresentative. Worth a task; it is not this one.
